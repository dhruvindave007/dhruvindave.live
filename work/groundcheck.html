groundcheck

Do language models cite real evidence? A benchmark where a model answers a question from an event log and must name the log lines that support its answer. groundcheck scores those citations.

Problem

In Office Vision Twin an LLM investigator explains security incidents and must cite the event IDs behind each claim. A citation is only useful if it points at a line that exists, covers all the evidence, and leaves out lines that merely look related. Answer accuracy alone hides all three failures: a model can be right for the wrong reasons, or cite an ID that was never in the log.

groundcheck takes that check out of the product and makes it a benchmark any model can be run on.

Approach

Each scenario is a question, an event log with stable IDs, a gold answer, the minimal set of evidence lines, and labelled decoys. There are 123 scenarios. 27 are office incidents ported from Office Vision Twin. 96 are generated server logs, where a seeded generator sets the log length (20 to 200 lines), the share of decoys (0 to 75%), where the evidence sits, and the ID format. 31 scenarios have no answer in the log, to test whether a model says so instead of inventing one.

Scores per scenario are citation precision, recall and F1; the share of answers citing an ID that does not exist; the share of citations that are decoys; answer accuracy; grounded accuracy, which counts a right answer only if its citations are also right; and correct abstention. Every mean comes with a bootstrap 95% confidence interval over scenarios. The metrics have unit tests with hand-computed cases.

Three baselines that use no language model bound the scores: random lines, BM25 keyword search, and the answer key. BM25 reaches a citation F1 of 0.74, but drops from 1.00 to about 0.65–0.70 once decoys are present, because decoys share its keywords. In this example it finds the crash and misses its cause.

Limits

No language model has been scored yet; the published numbers are baselines only. Adapters for Anthropic, Amazon Bedrock and any OpenAI-compatible server, including local Ollama, are in the repository, and replies are cached so reruns are free.

The server-log scenarios come from four templates, so a model could learn them; they are a controlled probe, not a natural sample. 27 office scenarios give wide confidence intervals. Answer correctness is exact matching on entities, numbers and yes/no, not a judge model.

Code

Scenarios, metrics, adapters and results are on GitHub under Apache-2.0. One command reruns every baseline.
